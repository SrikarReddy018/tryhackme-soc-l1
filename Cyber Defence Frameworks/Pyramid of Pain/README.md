# TryHackMe: Pyramid of Pain

## Overview

The Pyramid of Pain is a cybersecurity concept that explains how different indicators of compromise (IOCs) affect an attacker's ability to continue their operations without being detected.

It is used by cybersecurity teams and threat intelligence platforms to improve Cyber Threat Intelligence (CTI), threat hunting, and incident response.

The pyramid contains seven levels, starting with hash values at the bottom and progressing to Tactics, Techniques, and Procedures (TTPs) at the top. As defenders move higher up the pyramid, they focus on indicators that generally require attackers to make more significant changes to their infrastructure, tools, or behavior.

## What I Learned

### 1. Hash Values

**Difficulty: Trivial**

A hash value is a fixed-length value generated by applying a hashing algorithm to data. It can be used to identify a file and is commonly used as an indicator of compromise.

The room covered several hashing algorithms:

* **MD5:** Produces a 128-bit hash. It is no longer considered cryptographically secure because of known collision vulnerabilities and attacks.
* **SHA-1:** Produces a 160-bit hash, commonly represented as 40 hexadecimal characters. NIST has deprecated SHA-1 for security-sensitive applications and recommends stronger alternatives.
* **SHA-2:** A family of hashing algorithms that includes SHA-256, which produces a 256-bit hash represented as 64 hexadecimal characters.

Hashes help analysts identify suspicious files and known malware samples. However, even a small modification to a file can produce a different hash. This makes hash-based detection relatively easy for attackers to evade by modifying their files.

The room demonstrated this concept by appending a string to an OpenVPN MSI file and observing how its MD5 hash changed.

### 2. IP Addresses

**Difficulty: Easy**

An IP address identifies a device or network interface communicating over an IP network.

Defenders can block malicious IP addresses using firewalls and other security controls. However, attackers can change their public IP addresses or move their infrastructure to different addresses.

The room also introduced **Fast Flux**, a DNS technique in which a domain is associated with multiple changing IP addresses. Botnets can use this technique to hide infrastructure involved in phishing, proxying, malware delivery, and Command and Control (C2) communications.

Because IP addresses can be changed relatively easily, blocking an IP address does not necessarily eliminate the underlying threat.

### 3. Domain Names

**Difficulty: Simple**

Domain names provide human-readable names that can resolve to IP addresses through the Domain Name System (DNS).

A domain name can contain a second-level domain and a top-level domain (TLD), with an optional subdomain.

The room covered several ways domain names can be used or manipulated by attackers:

* **Changing domains:** Attackers may register or switch to different domains to avoid detection. Some DNS providers and APIs can make changes easier.
* **Punycode:** An encoding system that represents certain Unicode characters in an ASCII-compatible format. Attackers can abuse visually similar characters to create deceptive domain names, a technique associated with homograph attacks.
* **URL shorteners:** These services can hide the destination of a link, making it harder to determine where it leads just by looking at the shortened URL.
* **Proxy and web server logs:** These logs can help analysts identify requests involving suspicious domains.

The room also introduced the ANY.RUN malware-analysis sandbox. Its Networking tab can display information such as HTTP requests, network connections, and DNS requests generated during analysis.

An important safety point is to avoid directly visiting suspicious IP addresses or URLs found in malware reports.

### 4. Host Artifacts

**Difficulty: Annoying**

Host artifacts are traces left on a system as a result of malicious activity. They can help analysts identify suspicious behavior and investigate potentially compromised devices.

Examples include:

* Suspicious registry values.
* Unusual process execution.
* Files created or modified by malware.
* Dropped malicious executables.
* Other threat-specific artifacts and indicators.

The room demonstrated suspicious process execution originating from Microsoft Word and the creation or modification of files following the opening of a malicious application.

Detecting host artifacts can force attackers to change their tools, techniques, or methodologies, requiring additional effort to avoid detection.

### 5. Network Artifacts

**Difficulty: Annoying**

Network artifacts are observable characteristics of network traffic that can help identify malicious activity.

The room covered examples such as:

* **User-Agent strings:** HTTP request headers that identify the software or client making a request.
* **Command and Control information:** Network indicators associated with communications between compromised systems and attacker-controlled infrastructure.
* **URI patterns:** Patterns in HTTP request paths that may help identify suspicious activity.

Network artifacts can be investigated using packet captures and network security tools.

The room introduced:

* **Wireshark:** A tool for inspecting network traffic.
* **TShark:** A command-line tool for capturing and analyzing packets.
* **Snort:** An intrusion detection system that can generate alerts based on network traffic and detection rules.

The room also included examples of User-Agent strings associated with Emotet.

I learned that examining network traffic can reveal suspicious communication patterns that may remain useful even when an attacker changes file hashes or IP addresses.

### 6. Tools

**Difficulty: Challenging**

This level focuses on the tools and utilities attackers use to carry out their activities.

The room covered tools used to:

* Create malicious documents containing macros for spear-phishing campaigns.
* Establish backdoors for Command and Control communications.
* Create custom executable or DLL files.
* Deliver payloads.
* Crack passwords.

One example involved a Trojan dropping a suspicious executable named `Stealer.exe` into a temporary directory and then executing it.

Defenders can identify malicious tools through antivirus signatures, detection rules, and YARA rules.

The room introduced several resources used in malware analysis and detection engineering:

* **MalwareBazaar:** A resource for malware samples and related information.
* **Malshare:** A resource providing malware samples and feeds.
* **SOC Prime Threat Detection Marketplace:** A platform for sharing detection rules, including rules related to vulnerabilities being exploited in the wild.
* **SSDeep:** A tool associated with fuzzy hashing that can help compare files for similarity despite certain differences between them.

Fuzzy hashing is useful because attackers may modify malware without completely changing its underlying structure or characteristics. Similarity analysis can help analysts identify related files.

### 7. Tactics, Techniques, and Procedures (TTPs)

**Difficulty: Tough**

TTPs describe the tactics, techniques, and procedures adversaries use to achieve their objectives.

They can cover an attacker's activities throughout an intrusion, from initial access through phishing to persistence, lateral movement, and data exfiltration.

The room introduced the **MITRE ATT&CK framework**, which organizes documented adversary tactics and techniques.

Unlike individual indicators such as hashes or IP addresses, TTPs focus on how attackers operate. Detecting these behaviors can make it more difficult for an attacker to continue an operation without changing their approach significantly.

The room used Pass-the-Hash as an example of an attack that defenders may investigate through Windows Event Log monitoring. Identifying suspicious activity can help analysts determine which host has been compromised and take steps to prevent further lateral movement.

When defenders detect and respond to an attacker's TTPs, the attacker may need to research new techniques, retrain, reconfigure tools, or abandon the operation.

## Practical Lab

### The Pyramid of Pain Exercise

The practical task involved using the static site provided by TryHackMe to place prompts into the appropriate levels of the Pyramid of Pain.

The objective was to associate different indicators and attacker behaviors with their corresponding tiers.

The pyramid follows this order, from bottom to top:

| Level | Indicator         | Difficulty  |
| ----- | ----------------- | ----------- |
| 1     | Hash Values       | Trivial     |
| 2     | IP Addresses      | Easy        |
| 3     | Domain Names      | Simple      |
| 4     | Host Artifacts    | Annoying    |
| 5     | Network Artifacts | Annoying    |
| 6     | Tools             | Challenging |
| 7     | TTPs              | Tough       |

This exercise reinforced the differences between the seven levels and how they relate to the effort required for an attacker to adapt.

### Applying the Concept to Threat Hunting

The room also suggested researching an Advanced Persistent Threat (APT) group and examining its known indicators.

The recommended approach is to:

1. Select an APT group to research.
2. Identify its known indicators and attack techniques.
3. Consider which detection rules or defensive approaches could identify its activity.
4. Determine where those indicators and detections fit within the Pyramid of Pain.

The room provides Rapid7's APT Groups resource as a starting point for this research.

## Key Takeaways

* Hash values are useful for identifying known files, but modifying a file can change its hash.
* IP addresses can be blocked, but attackers may change their infrastructure.
* Domain names provide useful indicators for investigating suspicious activity, although attackers can change domains or disguise links.
* Host artifacts help analysts investigate suspicious activity on individual systems.
* Network artifacts can reveal suspicious communications and traffic patterns.
* Malware analysis resources, antivirus signatures, detection rules, and YARA rules can help identify malicious tools.
* Fuzzy hashing can help identify similarities between files that have been modified.
* TTP-based detection focuses on attacker behavior and can make evasion more difficult.
* The Pyramid of Pain helps explain why some indicators are more valuable for disrupting an attacker's operations than others.

## Conclusion

The Pyramid of Pain demonstrates how different types of indicators can support threat detection, threat hunting, and incident response.

At the lower levels, attackers may be able to change indicators such as file hashes and IP addresses relatively easily. Higher levels focus on host and network artifacts, tools, and attacker behavior, which can require more effort to change.

Understanding these differences helps security analysts think beyond individual indicators and consider how attackers operate.

The room also reinforces the importance of threat intelligence, malware analysis, log investigation, and detection engineering when building effective defenses.
