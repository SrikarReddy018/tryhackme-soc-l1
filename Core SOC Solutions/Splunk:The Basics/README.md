# Splunk: The Basics

## Overview

This TryHackMe room introduced me to the fundamentals of **Splunk**, a widely used platform for collecting, searching, analyzing, and correlating machine-generated data.

The room focused on understanding how Splunk works as a SIEM, its main components, the Splunk interface, log ingestion, and using **SPL (Search Processing Language)** to search and analyze logs.

---

## What I Learned

### What is Splunk?

Splunk collects and analyzes data generated by different systems and devices, including Windows and Linux systems, web servers, firewalls, VPNs, databases, and applications.

Instead of manually checking logs from individual systems, Splunk provides a centralized platform for searching and analyzing this data.

**Log Sources → Splunk → Search & Analysis → Investigation**

---

## Splunk's Core Components

Splunk has three main components:

**Forwarder → Indexer → Search Head**

### Forwarder

A lightweight agent that collects data from monitored systems and sends it to the Splunk Indexer.

**Forwarder = Collects and forwards data**

### Indexer

Receives, parses, normalizes, and stores the data as searchable events.

**Indexer = Processes and stores data**

### Search Head

Provides the interface for searching indexed data using **SPL** and displaying results through tables and visualizations.

**Search Head = Searches, analyzes, and visualizes data**

## Practical Lab

The practical part of the room involved **ingesting and analyzing VPN logs** in Splunk.

### 1. Uploading the Logs

I uploaded the provided `VPN_logs` file into the Splunk instance using **Add Data → Upload**.

The ingestion process consisted of five steps:

1. **Select Source**: Selected the `VPN_logs` file.
2. **Select Source Type**: Used the detected **JSON** format.
3. **Input Settings**: Stored the data in the `VPN_Logs` index and configured the associated host.
4. **Review**: Checked the ingestion settings.
5. **Done**: Completed the upload.

The VPN log file was **newline-delimited JSON**, meaning each line represented an individual event.

After uploading the data, I opened **Search & Reporting** and set the time range to **All time**.

### 2. Verifying the Imported Data

I first checked whether the logs were successfully ingested:

```spl
index=VPN_Logs
| stats count
```

This searches the `VPN_Logs` index and counts the available events.

### 3. Extracting JSON Fields

Since the VPN logs were JSON data, I used `spath` to extract the fields:

```spl
index=VPN_Logs
| spath
```

Some of the fields available in the dataset included:

* `UserName`
* `Source_ip`
* `Source_Country`

### 4. Investigating an IP Address

I used SPL to investigate activity associated with a specific source IP:

```spl
index=VPN_Logs
| spath
| search Source_ip="107.14.182.38"
| stats values(UserName) as UserName count
```

This query:

* Searches the `VPN_Logs` index
* Extracts the JSON fields
* Filters events matching the specified source IP
* Shows the unique usernames associated with the IP
* Counts the matching events

This demonstrated how an analyst can start with an IP address and identify related user activity.

### 5. Investigating User Activity

I also searched for activity associated with a specific username:

```spl
index=VPN_Logs
| spath
| search UserName="Maleena"
| stats count
```

This filters the events to those associated with the specified user and counts the matching results.

Overall, the practical lab helped me understand how raw VPN logs can be ingested into Splunk and then investigated using fields such as usernames, IP addresses, and countries.

## Important SPL Concepts

### `search`

Filters events based on specific conditions.

### `spath`

Extracts fields from structured JSON data.

### `stats`

Summarizes search results using calculations such as counts and unique values.

### `values()`

Returns unique values for a field.

---

## Important Splunk Concepts

### Index

An **index** is where Splunk stores indexed data.

In this lab:

```text
VPN_Logs
```

was used to store the VPN events.

### Event

An **event** represents an individual piece of data recorded by Splunk.

### Field

A **field** contains a specific piece of information within an event, such as:

```text
UserName
Source_ip
Source_Country
```

### SPL

**Search Processing Language (SPL)** is Splunk's query language for searching and analyzing indexed data.

---

## Overall Splunk Workflow

```text
Log Sources
     ↓
Forwarder
     ↓
Indexer
     ↓
Search Head
     ↓
SPL Queries
     ↓
Analysis
```

This shows how data moves from its original source through Splunk and eventually becomes searchable information for an analyst.

---

## Key Takeaways

* Splunk provides centralized collection and analysis of log data.
* **Forwarder → Indexer → Search Head** is the basic Splunk architecture.
* The Indexer processes and stores events.
* The Search Head allows analysts to search and visualize data.
* **SPL** is used to investigate indexed data.
* `spath` is useful for extracting fields from JSON logs.
* `search` filters events, while `stats` summarizes them.
* Indexes, events, and fields are fundamental concepts when working with Splunk.
* Log data can be searched to investigate users, IP addresses, and activity patterns.
